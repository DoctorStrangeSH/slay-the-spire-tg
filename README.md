## Об игре

Slay And Spire — одиночная карточная roguelike-игра в сеттинге тёмного фэнтези. Выберите героя, собирайте колоду и реликвии, прокладывайте маршрут через процедурные этажи и переживите три акта Шпиля.

### Герои

| Герой | Стиль игры | Ключевая особенность |
|---|---|---|
| **Берсерк** | Агрессия и риск | Здоровье, раны и опасные усиления |
| **Инженер** | Контроль поля | Турели, дроны и другие конструкции |
| **Псайкер** | Контроль и комбинации | Паралич, предвидение и эхо |

### Игровой цикл

- Процедурная карта с выбором маршрута и разными типами комнат.
- Пошаговые сражения с картами, энергией, блоком, статусами и намерениями противников.
- Награды, улучшения, реликвии, магазины, сокровищницы и события.
- Три акта с боссами и секретная встреча, зависящая от решений игрока.
- Локальное сохранение текущего забега, история прохождений и достижения.

## Локальный запуск

Сборка и пакетный менеджер не требуются: клиент — статический HTML, CSS и JavaScript.

1. Установите Node.js 22 или новее (для запуска тестов).
2. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/DoctorStrangeSH/slay-the-spire-tg.git
   cd slay-the-spire-tg
   ```
3. Запустите локальный HTTP-сервер из корня проекта:
   ```bash
   python -m http.server 8000
   ```
4. Откройте [http://localhost:8000](http://localhost:8000).

Можно использовать любой другой статический HTTP-сервер. Открытие через `file://` не рекомендуется.

## Проверки

Полный набор регрессионных тестов:

```bash
node --test tests/*.test.cjs
```

Проверка синтаксиса JavaScript:

```bash
find js tests -type f \( -name '*.js' -o -name '*.cjs' \) -print0 | xargs -0 -n1 node --check
```

Те же проверки выполняются GitHub Actions при push в `main` и при создании pull request. Тесты используют встроенный Node.js Test Runner — сторонние npm-пакеты для них не нужны.

## Разработка

- Изменения должны соответствовать ТЗ и отмечаться в дорожной карте.
- Перед отправкой изменений запускайте синтаксическую проверку и полный набор тестов.
- Для изменений JavaScript или CSS обновляйте версию сборки и query-параметры ресурсов в `index.html` по правилам [DEPLOYMENT.md](docs/DEPLOYMENT.md).
- Не добавляйте токены, локальные сохранения, логи, результаты тестов и собранные артефакты в Git.
- Сохраняйте комментарии, объясняющие важные игровые инварианты; удаляйте устаревшие и дублирующие пояснения вместе с соответствующим кодом.
